# Continuous build and data maintenance: implementation package

Designed **18 October 2026 AEST** (17 October UTC). Design and isolated validation only. No schedule, Worker, credential, CI workflow or publishing setting was changed. Start with this document, then [system and incident contracts](SYSTEM.md) and [dependency-ordered execution](EXECUTION.md).

## Decision

Complete a **finite, named set of supported tasks** for the eight published desks, with one repair in progress at a time. Maintain those obligations continuously; adding another source becomes a separate scope decision. This replaces the repository's older “search until an empty pass” stopping rule for this task. It does not authorize removal of existing sources.

Use the existing Worker and verification code. The proposed operational addition is one deterministic verifier with durable checkpoints, running through GitHub Actions **only after its deployment coupling and access are proven safe**. Reuse the existing Codex watch for independent heartbeat/notification review. No new database, queue, MCP server or Cloudflare service is justified now. This is a gated design, not a claim that remote CI or artifact persistence already works.

The first implementation work is checkpoint/incident reconciliation and source-level monitoring coverage. The first proposed source repair is the existing UK CPI reader: it combines index and annual-change calls without explicitly joining their periods, while ONS access is blocked. Matching HTTP successes could otherwise produce a believable mixed-month answer. This is a concrete risk in the chosen task set, not proof it outranks every unaudited native reader. Inspect original metadata and exact periods before changing it; a different economic series is not an acceptable fallback.

## Prioritized build queue and stopping discipline

| Order | Bounded outcome | Entry / exit and blocked handling |
| --- | --- | --- |
| 0 | Reconcile the monitoring baseline, known incidents and current source registry; checkpoint/alert shadow mode | Fresh public audit + baseline import. No alert on import; no missing checkpoint resets. Exit after restart and duplicate-run exercises plus reviewed current incident states. |
| 1 | Protect exact definitions for the ten task targets above; first data repair UK CPI period join | One source contract per change. Existing `D7BT`/`D7G7` paths and original metadata are inputs. Exit with joined periods, publisher reconciliation and live preview; blocked access gets at most two bounded investigation sessions before parking. Move to next independent task, not a different economic measure. |
| 2 | Finish evidence gaps for BoC four FX pairs, England pharmacies and Scottish/NI insolvencies | Reuse readers/fixtures; no new datasets. Each task closes only on G. Missing independent presentation stays an explicit limitation, requiring a justified review of extraction evidence. |
| 3 | Make monitoring refresh load safe; implement checkpoints and collector | Measure cold fetch fan-out first. Fix whole-desk degraded-cache amplification only if quota/budget gate fails. Keep failure health visible and never extend data beyond its contract to gain cache hits. |
| 4 | Validate scheduler, checkpoint store, watchdog and notification delivery | Manual/shadow runs first. Activation requires all execution gates and separately authorized scheduling/notification configuration. |
| 5 | Close seven-day observation window and per-desk acceptance record | All task gates pass or explicitly remain blocked. Publish a finite completion report; continue maintenance, not open-ended discovery. |

WIP: one implementation/repair, one independently reproducible verification packet; no concurrent release from another branch. Rank new tickets by (1) plausible wrong answer / lost core contract, (2) unavailable supported task, (3) evidence gap, (4) convenience, then dependency and publisher cost. An upstream 403 does not outrank silently wrong units merely because it is easy to count. Keep one ticket per incident/contract. Two failed source-access investigations, or one missing licence decision, park the item with evidence, owner, unblock condition and next review date; do not keep an agent polling or changing user credentials.

Maintenance can create a bounded repair item with source IDs, impact, last good evidence and reproducer. It cannot add sources or redefine country completion. Read-only retries and deterministic validation may run automatically; patches and dependency upgrades can be prepared for review. Production promotion, schema-breaking changes, credential edits, new paid infrastructure and new supported coverage require the established authorization/release process.
