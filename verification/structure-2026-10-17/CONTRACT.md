# Information contract — defined before implementation

Scope: existing eight desks and existing readers. No new source, database, MCP server or automatic build. This is a navigation and representation change, with narrow validation where a representation would otherwise manufacture a number.

## Measured problems and chosen structure

Public probes at 10:13–10:16 UTC on 17 October 2026 established: the well-known catalogue describes Australia alone; the root catalogue has eight links but no source/measure directory; no response validator is provided; a request for `canada.json?date=2026-10-12` returns the latest 16 October values with HTTP 200; the sitemap returns 404. Full desk bodies range from 8,582 to 71,042 bytes. Wales projection and NI BMI already retain strong semantics; Canadian FX lacks quote units and publisher links. Keep those successful native fields and readers.

The minimal change is a two-level catalogue on the existing catalogue URL, selected responses on existing desk URLs, a linked schema/usage contract, canonical links and conditional HTTP requests. A sitemap repairs the broken discovery path. Do not add search, arbitrary query execution, historical storage or a new protocol. Source selection initially reuses the cached complete desk: it reduces client bytes, not necessarily publisher calls or cold-request latency.

## Identity, semantics and compatibility

- Canonical origin is `https://morningrows.com`; www and `/morning.json` remain usable. Desk ID is its canonical JSON URL. Source ID is that URL plus `?source=<existing section key>`. Nested sections use dotted keys such as `also.world` where appropriate.
- A source is a reader section, not a claim that it is a unique publisher. Catalogue entries retain section paths and distinguish explicitly described measures from native-only sections. Native-only sections retain original fields; absent metadata is **unknown**, never inferred from the desk name. Do not promise common observation identifiers for unreviewed event lists.
- Described measure IDs are immutable within the selected source. Publisher codes are used where present; composite AIHW IDs include jurisdiction and triage code. Definition changes require new IDs. The fixed population, geography, unit, adjustment and other selected dimensions belong to the definition, not the numeric value.
- Observation identity is the measure URL plus `&observation=<exact source period>`. The URL selects that period only if it is currently retained. A missing former period returns an explicit not-retained response, never today's value. It is a stable identity, **not an archival guarantee**. Consumers retain the response, publisher citation and content version for historical audit.
- Full desk fields and types are preserved; `_meta` is additive. Selected responses are opt-in and have schema version `1.0`. Root `countries`, `page`, `records` and Australia alias stay compatible. Unknown parameters, duplicate selectors, unknown sources/measures and unsupported versions fail explicitly. Unsupported geography/date filters cannot be ignored. Additive schema changes may increase the minor version; breaking changes need another major version and migration documentation.
- Every described observation supplies value state, unit, geography, population/selected dimensions, adjustment (null when unestablished), period code and convention, kind (including projection), publisher URL/licence and caveats. Native source data accompanies source-level responses so qualifications survive. Measure-level responses retain source context without unrelated rows.
- Numeric zero is `observed`; null is never coerced. Explicit suppression is `suppressed`; an absent published value is `missing` or `unavailable` as supported by the publisher; failed retrieval is `retrieval_failed`, separate from observation state. If an old reader conflates missing and suppression, report uncertainty rather than infer a specific state. Preserve successful sibling sources and rows.

## Time and return visits

- `period` is the observation reference period and preserves financial/academic/calendar/interval conventions. Publisher release/upload/update fields retain their named meaning. `published_at` is null unless established; dataset update time is not silently relabelled as publication time. `retrieved_at` is the reader's actual attempt time, including failures, not response-render time. Expected next publication is null unless established by source metadata. Cache expiry is not publication cadence.
- Weak ETags identify semantically equivalent responses while excluding only explicitly designated retrieval timestamps. Values, periods, definition/caveats, publisher version/status and failures contribute to versions. Conditional GET and HEAD work on canonical and alias URLs. A 304 means this selected representation is unchanged, including health; it does not mean the publisher was fetched on that request. Expose the retained retrieval time and honour cache age.
- Clients compare measure/observation IDs and content versions: new period means a newly available observation; same identity with changed content means a revision or metadata correction; identical content remains valid without a daily change; failed retrieval remains a failure, never a successful fresh observation. Publisher release time/status is needed to call a change an official new release. No server history means no fabricated previous value or change classification.
- Never calculate staleness from “did the value change today”. Publication cadence is descriptive and may be unknown. Retain explicit existing delays, interim status and revision caveats.

Preview finding, 10:27 UTC: `caches.default.match` returned a four-hour `Cache-Control` on previously stored 30-second degraded snapshots. Before release, enforce a stored absolute expiry in the Worker and restore the bounded remaining TTL on cache hits. Test an expired cached body despite permissive edge headers; no infrastructure or account-level cache rule change is required.

## Acceptance criteria

1. All eight desks and every existing reader section are discoverable from the root catalogue, with a source URL; the well-known file no longer implies Australia-only coverage. Search/retrieval agents can fetch discovery files; training-crawler restrictions are preserved. Verify actual edge headers and robots output, including Cloudflare-managed content.
2. Demonstrate source and measure selection with Canada FX, all 23 Stats NZ series, AIHW's eight jurisdictions × five triage categories, Wales projection, NI BMI and existing national insolvency/pharmacy measures. Unknown or unsupported selections return explicit errors. No rent/claimant/history research prototype is advertised as deployed data.
3. Before/after constructed journeys use the same source snapshot for answer comparison and exact request/byte traces for retrieval effort. Separate held-out cases (different measure, nation, incompatible period/unit and missingness) from examples used to design the interface. Check reference values against retained publisher evidence where available and identify extraction-lineage limitations.
4. Test wrong geography, period and units; zero versus suppression; partial responses; unchanged refetch; revised value; changed caveat; new period; failure/recovery; conditional requests; cached/noncached query isolation; old URLs and source failure isolation. Selected valid responses must contain enough context to cite and qualify the answer.
5. Validate actual implementation in Cloudflare remote preview. Release with the established Wrangler workflow, preserve secrets and avoid main/automatic Builds. Both domains must match the clean release identity; all eight desks retain working sources and all established regression contracts pass. Investigate unexpected source failures against the captured pre-change state.
6. Report measured deterministic results separately from independent agent evaluations. An unavailable client, inaccessible historical log service or absent adoption evidence is a limitation, not a successful test. Do not claim agents will return more often from a structural check alone.

## Evidence basis and evaluation boundary

The prior [project research](../../research/project-demand-2026-10-17/README.md) cites an actual [OpenBB historical-FX request](https://github.com/OpenBB-finance/OpenBB/issues/7490), [BoC agent workflow](https://github.com/arose26/bank-of-canada-mcp), [Nomis worked examples](https://github.com/brynmrgn/ons-mcp/blob/main/EXAMPLES.md), [AEMO workflow](https://github.com/Bigred97/aemo-mcp), and [author-reported ONS retrieval trace](https://github.com/chris-page-gov/okf-ons/blob/main/research/2026-07-18-claude-desktop-cowork-fable-5-okf-ons-access-trace.md). These ground the date/geography/units/citation/payload tasks. The exact Morning Rows test questions are constructed; no production user query counts or private request logs were available. Government validation cases extend those structural tasks to existing verified readers; they are not observed demand for those specific measures.

Development set: first discovery; Canada current reference conversion and unsupported holiday date; Wales projection qualification; NZ measure selection; Scotland/NI same-measure geography distinction; unchanged revisit. Held-out: a different NZ measure, AIHW urgent WA versus NSW, NI academic-year BMI versus calendar-year assumptions, England pharmacy stock versus monthly flow, and source failure/recovery. Do not tune reference figures to outputs.
