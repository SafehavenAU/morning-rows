# Exact cold-path optimization — before runtime changes

20 October 2026 UTC. The user authorized further optimization on Workers Free.
The existing actual cold measurement remains 29 ms; the release limit is 10 ms.
No new statistical measure, publisher, transport, response schema or fingerprint
algorithm is authorized by this experiment.

The candidate combines two local prototypes: scan the two target table opening
tags once and slice their original bodies; reuse canonical JSON fragments for
the fixed CPI definition and selected-response envelope. Keep every existing
catalogue, period, coverage, revision and missing-value validation. Reject
ambiguous target IDs. Hash the same original publisher text. Keep all response
fields, self-contained observation definitions and exact fingerprint bytes.

Canonical composition applies only to the known row shape. Additional properties
must use generic canonical serialization; they must never disappear from a hash.
Nested footnote keys and numeric or lexically late additional keys are explicit
adversarial cases. Independently reconstruct observation versions, content
versions and ETags with the existing generic semantic/SHA-256 algorithm. Check
GET, HEAD, conditional, failure and exact-observation behavior.

Local Node and workerd profiles are diagnostic. The direct workerd comparison
uses fresh isolates, retained inputs, no cache and no external network. The
combined candidate reduced repeated-read sample count by about 21%; first-read
attributed-time ranges overlap. This supports one bounded edge investigation,
not a reliable CPU improvement or a passing 10 ms result.

Run the complete local suite, independent extraction/schema checks and protected
Cloudflare reader scenarios before CPU assessment. Upload a clean candidate
version and stage it at 0% beside approved production at 100%. Use the hardened
version/path/time-correlated verifier with fresh publisher retrieval. Retain the
result even when it fails. A failed first capture ends this candidate attempt;
do not repeat unchanged uploads to seek a lucky result.

Release still requires one complete cold capture and two fresh confirmations,
each at most 10 ms, plus final both-domain, all-desk and core-contract acceptance.
On failure restore approved production as the sole active version and remove
unjustified runtime complexity. Preserve the prototype and evidence for audit.
Do not change billing, credentials, bindings, routes, automatic Builds, monitoring
scope, schedules, checkpoints or notification state.
